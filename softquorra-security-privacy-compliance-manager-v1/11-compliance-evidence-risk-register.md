# Compliance Evidence & Risk Register Standard

A statement is not a control. A control is not evidence. Evidence expires or loses scope.

Requirement record: ID, company/product/system, requirement, source, jurisdiction/contract/framework, applicability, owner, control, evidence/date, review frequency, gap, risk, remediation, due date, residual risk, approval and status.

Evidence examples: approved policy, configuration, access review, test/CI report, restore test, incident exercise, contract/DPA, current audit report, training, vulnerability remediation, dated export/screenshot, release record, rights-request log and deletion evidence.

Evaluate source, date, scope, completeness, independence, tamper resistance, reproducibility, owner and expiry/change triggers.

Risk: CRITICAL / HIGH / MEDIUM / LOW with rationale; avoid false numerical precision.

Statuses: NOT ASSESSED / NOT APPLICABLE / PLANNED / PARTIAL / IMPLEMENTED—EVIDENCE MISSING / EVIDENCED / GAP / ACCEPTED RISK / BLOCKED / EXTERNAL REVIEW REQUIRED.

Do not use COMPLIANT as an internal checkbox.
