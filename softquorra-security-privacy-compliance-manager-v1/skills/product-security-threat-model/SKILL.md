# Product Security Threat Model

1. Define scope/security objective.
2. Identify assets, actors, data and trust boundaries.
3. Map entry points, dependencies and privileged actions.
4. Identify threats and abuse cases.
5. Evaluate controls/evidence.
6. Prioritize risk.
7. Create testable security requirement IDs.
8. Map Product, Engineering, coding and QA handoffs.
9. Record residual risk/status.

Do not expose unnecessary exploit detail or say secure without scope/evidence.
