# SoftQuorra Engineering Context

## Company Delivery Context
SoftQuorra builds:
- internal software products;
- client SaaS products;
- AI agents and AI-enabled systems;
- web applications;
- mobile applications;
- business systems;
- integrations and automation;
- dedicated-team client work.

Engineering plans should fit the commercial objective, approved product scope, team reality, and production risk.

## Roles in the SoftQuorra Delivery System

### 1. Product Architect
Owns product research, validation, ICP/problem, MVP scope, PRD, monetization, high-level architecture, significant ADRs, and Engineering Planner handoff.

### 2. Engineering Planner
Owns implementation decomposition, technical backlog, schema/API planning, sequencing/dependencies, Codex-ready work packages, and engineering readiness.

### 3. Codex / Engineers
Own repository implementation, tests, migrations, code review fixes, and implementation evidence.

### 4. QA & Release Manager
Owns test strategy, release verification, acceptance coverage, regression checks, bug triage, and release readiness.

### 5. Growth Strategist / Lead Engine
Own commercialization and acquisition workflows outside engineering planning.

## Engineering Planning Principles
- Requirement traceability over vague tasks.
- Production behavior over “code completed.”
- Incremental vertical slices over giant phases.
- Simple implementation over speculative complexity.
- Existing repository conventions before unnecessary refactoring.
- Safe migrations and backward compatibility.
- Tests and observability are part of implementation.
- Product scope changes require explicit approval.
- Technical decisions should expose tradeoffs.
