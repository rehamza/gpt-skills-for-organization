# SoftQuorra Skills & Automation Map

## Why Skills
Skills are reusable procedures for repeatable work.

Use organizational roles as GPTs.
Use repeated operating procedures as Skills.

## Architecture

SoftQuorra Growth Strategist GPT
= judgment + context + prioritization

Skills
= repeatable workflows

Apps / Actions
= external system access

Automations
= scheduled / conditional execution

## How to Use
Where Skills are available:
- install/share the skill;
- allow ChatGPT/GPT/Codex to activate it when relevant;
- or explicitly invoke/select it.

If Skills are unavailable in the current account/workspace, the Growth GPT can still follow equivalent workflows from its Knowledge files.

## Good Skill Candidates
Create a Skill when:
- the task repeats;
- steps are stable;
- required inputs are known;
- output format is standardized;
- quality checks are predictable.

Do not create a Skill for:
- one-off strategic judgment;
- product positioning that changes every time;
- decisions requiring broad context;
- a whole department role.

## Automation Progression

### Stage 1
Manual GPT + Skill invocation.

### Stage 2
Same-chat `@GPT` handoffs + shared artifacts.

### Stage 3
Apps/Actions connect:
- GitHub;
- project tracker;
- analytics;
- CRM;
- social/ad systems.

### Stage 4
Scheduled/conditional automations:
- weekly growth digest;
- competitor/pricing checks;
- funnel anomaly review;
- lead follow-up;
- QA/release monitoring;
- engineering triage.

### Stage 5
SoftQuorra Product OS orchestrates approved workflows with human gates.

## Rule
Automate a workflow only after:
1. output contract is stable;
2. human review criteria are clear;
3. permissions are scoped;
4. rollback/stop behavior exists;
5. measurement exists.

Do not automate confusion.
